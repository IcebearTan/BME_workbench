# BME Workbench 基础架构

工作台是独立项目，既有训练营承担身份来源，工作台承担内部协作与运营。目录位于同一个 BME 工作目录下不构成运行依赖。本仓库须能独立克隆、安装、测试和构建。

## 技术与目录

前端采用 Vue 3、Vite 5、Vue Router 4、Vuex 4、Element Plus 与 DewUI。原平台的视觉组件和设计变量以带来源版本的快照放在 packages 中，不复制教学路由、用户全局状态或商城认证客户端。

后端采用 Flask 3、SQLAlchemy 与 Flask-Migrate。开发和隔离测试使用本项目 SQLite，生产目标为独立 MySQL 数据库。可以复用服务器和数据库服务实例，但不跨库查询训练营业务表，不创建指向训练营表的外键。数据库变更须通过 migrations 显式执行。

## 三层身份责任

| 层次 | 所有者 | 判断 |
| --- | --- | --- |
| 账号认证与自然人标识 | 训练营身份服务 | 当前账号是谁，是否有效 |
| 工作台应用准入 | 训练营提供事实，工作台校验 | 社团资格是否有效，是否允许进入此应用 |
| 内部授权 | 工作台 | 可访问哪些工作区，有无治理权限 |

来源方角色不直接成为本地权限。中央 super_admin、教育邮箱、商城资格、职位显示名称均不构成本地治理授权。普通成员、协调员和治理能力按工作台自己的授权事实解释，治理也不意味着可读取所有私有事项。

## 本地主体模型

- Person 是中央自然人标识的最小映射，以 issuer 和外部 person_id 区分，不重复维护实名核验。
- Account 是中央登录账号映射，以 issuer 和 subject 唯一识别。多个 Account 可以指向一个 Person，但不会自动合并权限。
- PersonRestriction 保存人员在具体工作区的否决；同人换账号不能绕过。人员全局禁用也影响其所有映射账号。
- Membership 保存账号在本地工作区的 member 或 coordinator 角色。
- PermissionGrant 保存账号明确获得的本地治理权限。初期只实现治理概览只读权限，其余治理动作后续迁移。
- Session 保存独立工作台会话的摘要、到期时间、撤销状态和中央安全版本。
- LoginAttempt 与 CodeConsumption 保存浏览器绑定的登录尝试和一次性回调消费记录。
- AuditEvent 当前记录成功登录、会话撤销及本地治理授权的开通与撤销，不保存密码、一次性代码或会话原文。完整业务操作审计随后续功能迁移补齐。

账号归并导致既有 subject 的 person_id 变化时，首期拒绝自动重映射，转入显式迁移流程。历史事项作者、私有参与关系、人员否决和权限不能通过账号归并自动取并集。

## 工作台会话

沿用现有技术栈，但工作台自身使用服务端 opaque 会话：浏览器只保存随机 HttpOnly cookie，数据库只存其摘要。这使工作台会话可以独立撤销，且不需要把训练营 JWT、密码或商城凭据交给浏览器再跨应用保存。

生产使用 HTTPS、Secure cookie、SameSite=Lax；写入请求校验 Origin 和 CSRF。访问令牌和会话不得保存在 localStorage。UI 偏好可使用 workbench 专属键，与训练营应用状态分开。

## 接入方式与当前边界

身份适配器默认 DisabledProvider。HTTP provider 实现的是本仓库提出的新训练营接入契约，需要训练营侧新增授权、一次性代码兑换与当前资格查询端点，并注册工作台客户端后才能真实使用。不会尝试用现有 points-sso 接口替代。

浏览器登录经绑定 state 的授权跳转和 PKCE S256 保护；后端交换短期一次代码，校验身份及准入后建立工作台会话。每次受保护请求向来源方复核当前资格；来源不可用时失败关闭，不能使用旧准入快照继续放行。

实时检查会引入明确的身份服务依赖：训练营身份端不可用时，工作台受保护操作也不可用。若将来需要离线容忍，须单独定义有上限的授权缓存时效和撤权承诺，不能在异常处理中悄悄放行。

## 本轮范围

本轮建立身份模型、迁移、配置、接口、应用壳和验证。原有话题、任务、回复、交付、附件、通知及自动授权尚未迁移。功能入口只显示当前可用能力，不以虚构计数或不可用按钮表示完成。

生产域名、反向代理、HTTPS 证书、专用客户端密钥、训练营侧接口和存量数据迁移均属于后续接入步骤。本轮不部署或修改旧平台。
