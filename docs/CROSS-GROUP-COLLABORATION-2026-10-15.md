# 跨组协作与轻量创建

状态：2026-10-15，已按用户授权推送并部署。应用版本 `fcfbe195e06371851e7f835bd796c05b34191897`。沿用现有 Vue / Flask 与身份权限方案，无数据库结构变更。本轮仅检查相关功能。

## 当前问题与调整

原工作台已有事项级邀请、点名回应、任务转交和跨组交付，但创建任务时同时展示负责人、截止时间、优先级、验收人和验收标准。交付入口混在状态操作中，发起人无法在详情里持续查看交付进度；多组成员的候选目录也缺少完整组别标签。

本轮采用“先记录事项，再安排协作”：一个事项仍有一个归属工作区、一个主要负责人；跨组参与不改变组织任职或工作区授权。多个组各自承担独立成果时，分别发起交付，每个承接组拥有自己的关联任务。

## 创建流程

创建只保留类型、工作区、标题和可选简短说明。默认沿用当前工作区。

- 话题可以直接发布，也可保存草稿。创建页明确提示发布范围，并可展开调整，避免误公开。
- 任务只填标题即可保存为草稿，进入详情后通过“事项设置”补齐负责人和截止时间，再发布。草稿始终仅作者可见。
- 优先级、验收人、验收标准、完整正文和发布后的可见范围在事项设置中维护；附件在详情上传，参与人于发布后邀请。
- 创建请求复用幂等键。若发布失败，进入已保存的草稿，不重新创建。
- 设置使用打开时的版本，仅提交更改字段；遇到版本冲突保留输入、刷新详情，不覆盖其他人的修改。

## 三种合作方式

| 场景 | 入口与流程 | 责任与可见范围 |
| --- | --- | --- |
| 讨论方案、临时求助、共同准备 | 发布话题或任务 → 邀请成员一起协作 → 讨论 / 点名回应 → 形成结论 | 按组筛选、一次选多人；邀请只开放当前事项，原组其他事项不开放 |
| 另一组负责独立成果 | 已发布任务 → 请其他组承接 → 填目标组、用途、说明，可附期望时间和文件 → 对方核心接单 → 对方任务执行 / 验收 → 结果回到原事项 | 原事项保留原组归属；承接组只获得明确交付说明与固定版本文件，不自动获得源事项全文 |
| 同一任务更换主要负责人 | 转交负责人 → 对方确认 → 新负责人继续执行 | 沿用既有确认流程；与组对组交付分别处理 |

例如：活动组负责开放日整体筹备，可先邀请文宣组和硬件组成员讨论；确定需要海报和展示设备后，分别向文宣组、硬件组发起交付。临时交流不要求另建任务，独立成果则在各承接组分别跟踪。

## 详情页

- 头部保留事项设置和推进状态的操作；未完整配置的任务显示补齐设置提示。
- “协作”区提供一起讨论、请其他组承接两个入口，列出发起人及单独参与的成员。
- 多人邀请部分失败时逐人列明原因，只保留失败成员供重试，成功成员不重复提交。
- 当前负责人和验收人不能直接移除，须先调整任务角色。更换验收人后，原人的参与关系保留；需要收回访问时再明确移除。
- “跨组交付进度”显示发出与收到的交付、说明、期望时间、状态和结果。刷新页面后依然保留，待接单交付可撤回。
- 对关联事项的跳转按钮以实际读取权限决定，不因存在交付关系而放开全文。
- 接收方接单后直接进入承接任务。交付附件显示固定版本，只通过授权下载入口获取。

## 权限与任务约束

沿用实时 SSO 准入与本地成员资格，候选列表汇总有效本地多组任职与兼容组织归属。失效账号、人员封禁和工作区否决不能通过邀请或任务人员设置绕过。

草稿只有作者可改；发布后事项设置由作者或有读取权的本组协调员维护。负责人、截止时间发布后继续走已有改派 / 转交 / 改期命令，保留确认与原因。待验收、已完成和已取消的任务不能改验收人或验收标准。发布时重新校验人员资格，并仅为负责人、验收人建立事项级参与关系。

目标组目录仅列有效组，不代表发起人能读目标组的其他内容。交付包下载复核目标工作区授权、固定版本与文件关联；撤权后立即拒绝。源组后续上传的新版本不会替换已经交付的文件。

## 本轮接口与发布交接

- `PATCH /api/work/items/:id` 增加 `task` 设置对象：`assignee_user_id`、`due_at`、`priority`、`reviewer_user_id`、`accept_criteria`。
- `GET /api/work/items/:id/handoffs` 返回 `outgoing` / `incoming`，含状态、说明、结果、固定附件以及撤回和关联跳转权限。
- `/api/work/candidates` 增加 `groups: [{id, name}]`，保留原字段兼容旧页面。
- 不需要新增数据库迁移。已先发布后端，再切换前端；训练营和其他应用不需要配套更新。

定向检查覆盖任务草稿配置发布、跨组验收人、设置乐观锁、邀请否决、多组候选、交付接单完成、撤回、固定附件及撤权；浏览器覆盖轻创建、多人邀请部分重试、交付进度持久读取与设置异常。浏览器使用隔离模拟接口，不能替代生产真实 SSO 联调。

## 后续范围

暂不增加独立项目空间、流程审批引擎或自动把整组所有人加入事项。跨多组的大型项目可先使用“主事项 + 各组承接任务”。若后续出现大量并行事项，再基于真实使用量设计项目视图与汇总看板。

交付完成后承接任务再次打开，沿用既有规则：已交付状态不倒退。新的补充要求通过讨论明确后另发交付，避免已确认结果被静默改写。
