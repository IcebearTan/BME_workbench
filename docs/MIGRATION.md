# 原工作台功能迁移清单

当前身份地基是独立项目的起点，原系统仍是现有工作业务与数据的唯一写入来源。本轮不切换旧入口、不创建生产账号、不变更生产授权、不复制真实附件。

## 功能归属

| 功能 | 目标归属 | 当前迁移状态 |
| --- | --- | --- |
| 账号、自然人、实名、社团准入事实 | 训练营身份服务 | 保留；新接入端点待实现 |
| 外部身份映射、独立会话与资格校验 | 本仓后端 | 基础实现，等待真实身份联调 |
| 工作区、账号成员、人员否决、治理授权 | 本仓后端 | 基础模型与只读边界；旧数据未导入 |
| 原工作台壳与管理入口 | 本仓前端 | 独立基础外壳；旧页面尚未逐页迁入 |
| 话题、回复、任务命令、验收、转交 | 本仓工作业务 | 后续迁移 |
| 跨组交付、子组汇总、工作记录 | 本仓工作业务 | 后续迁移 |
| 私有附件、固定版本、下载权限 | 本仓工作业务 | 后续迁移 |
| 工作通知、提醒、后台调度 | 本仓工作业务 | 后续迁移，切换时禁止双跑 |
| 课程、营期、工单对象卡片 | 来源域摘要接口与本仓适配器 | 后续从直接查询改为受控接口 |
| 社团组树、任职、成员归属 | 现有唯一组织事实源 | 首期保留，可通过接口为工作台供给 |
| 工作区授权、接管、交接、紧急介入 | 工作台管理区 | 后续迁移，不依赖训练营管理员页面 |

## 身份映射与数据兼容

冻结并记录原平台 user ID、person ID 与新 issuer/subject 映射规则。新系统不能因七位补零差异、邮箱变化或显示姓名匹配而重复开户。记录原始业务 ID 与新系统 ID 对照，保留历史作者、授权来源、文件版本和审计归属。

原有进组自动授、任职自动升协调员和人员级否决需要单独列出保留行为。默认业务权限由工作台维护；如果继续自动授权，组织变化通过明确的集成模块供给，不能直接访问训练营数据库。现有授权不得在迁移时被扩大。

## 实施顺序

1. 完成训练营专用身份接入和真实回调联调，确定社团准入口径与撤权时效。
2. 迁移工作区、成员、授权和人员级限制，先只读核对，不切生产写入。
3. 按事项闭环、跨组交付、文件、通知调度、治理工具逐个迁移，复用旧系统状态机和验收案例。
4. 为课程、营期、工单以及账号归并建立跨项目契约。占用检查失败不能当作没有工作数据。
5. 在隔离环境验证完整历史样本和新旧权限矩阵，核对条数、关联、文件校验值、历史时间与审计。
6. 切换窗口内冻结旧写入、补齐增量、切换唯一写入方与调度器，旧 URL 兼容转发。
7. 观察和验收后退役旧项目中的工作实现。回退前保留切换后新增记录，不用旧备份覆盖新业务数据。

## 完成标准

原有功能均有对照证据；工作人员从新入口完成日常协作与管理；学习流程不再装载工作业务状态；独立仓库可离开旧仓安装与构建；工作台代码和数据库不直接依赖教学模型；权限、私有文件、人员否决、历史审计及通知语义不因迁移改变。
